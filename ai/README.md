## 一、三层记录体系

本仓库的大模型协作记录分三层，**职责不重叠、不得混用**。分层的唯一目的是让「AI 说过什么」「我们据此做了什么」「其中哪一步是错的、怎么发现的」三件事**各自可核验**。

| 层 | 位置 | 谁产生 | 作用 | 能不能改 |
|---|---|---|---|---|
| **原始层** | `ai/raw/` | **脚本导出**（客户端本地会话记录） | **逐字原文**，追溯的最终依据 | ❌ **任何人不得手改** |
| **整理层** | `ai/sessions/` | 人 + AI 整理 | 按「一件事」口径整理，**含自我纠错轨迹**，**是提交物** | ✅ 可修订（但不得改原始层引用） |
| **沉淀层** | `../skill/`（**仓库根**，不在本目录下） | 人 + AI 提炼，剥离题目专有信息 | 可复用技能包（换题目仍可用），**是提交物** | ✅ |

```
        对话（提示词 / 模型回答）            开发过程（综合报告 / 波形 / 板级实测）
                  │                                        │
                  ▼                                        ▼
             ai/raw/  ←── 脚本导出，逐字，不可手改 ──→ （证据来源）
                  │
                  ▼  按「一件事」整理、标注纠错轨迹、绑定证据
          ai/sessions/  ── 提交物（INDEX.md 是入口）
                  │
                  ▼  提炼、剥离专有信息、验证可复用性
             skill/      ── 提交物（指南 3.3.5.2 四形态）
```

### 1.1 原始层 `ai/raw/` —— 逐字，不可手改

| 要点 | 说明 |
|---|---|
| 谁产生 | **导出脚本**从客户端本地记录导出；**不允许手抄** |
| 为什么不能手抄 | 手抄必然漏、必然走样；而指南要求的是**原文**。**改写过的提示词「一看就假」**，反而扣分 |
| 为什么不可手改 | 它是证据链的根。一旦有人手改，「逐字」这个全称断言当场变假，且**不会有任何东西报错** |
| 平台风险 | 多数平台的会话记录只保留有限天数（常见约 30 天）⇒ **必须定期导出落盘**，不要依赖平台长期保存 |
| 换客户端风险 | 换客户端会**静默断链**（原文停更而无人发觉）⇒ 每换一次客户端，第一件事是跑一次导出脚本的 `--list` 确认能抓到新会话 |

### 1.2 整理层 `ai/sessions/` —— 提交级，含自我纠错轨迹

- 文件命名：`NNN_<slug>.md`（ASCII、小写下划线；`slug` 用英文短名）
- 字段固定：见 [`sessions/_TEMPLATE.md`](sessions/_TEMPLATE.md)；**每一项都必须能指向硬证据**
- 入口：[`sessions/INDEX.md`](sessions/INDEX.md)（新增记录**必须先写记录、后登记索引**，顺序不可反）
- **★ 自我纠错轨迹是本层最值钱的部分**，也是**唯一无法事后伪造**的部分 ——
  它必须带证据（综合 / 实现 / 时序报告、仿真波形、板级实测、官方文档**具体章节号**、仓库内原文）。
  可接受的证据清单与禁止用语见模板内「证据的可接受来源」。

### 1.3 沉淀层 `skill/` —— 换题目也能用的部分

沉淀层**位于仓库根的 `skill/`**（指南 3.3.5.4 的推荐目录结构），**不在 `ai/` 下**；
本目录只负责**从整理层问出问题**：

> **「这次有什么是换个题目也能用的？」** —— 有，就去 `skill/<name>/` 建包；没有，继续。

技能包必须含 `README.md` 说明**适用范围 / 使用方法 / 失效条件**（指南 3.3.5.2 硬要求）。
**边做边沉淀**：失败发生时的上下文（报错原文、波形、当时的误判、为什么走了弯路）**几个月后无法还原**，
等到结项再补写，只能写出空洞记录。

| | `ai/`（本目录） | [`../report/llm_logs/`](../report/llm_logs/) |

## 三、规则

- **命名**：本目录所有文件名 / 目录名**纯 ASCII**（`a-z 0-9 _ -` 与 `.`），禁止中文、空格、括号、全角字符；**中文只出现在文件正文**（承 `docs/repo_spec.md` §1）。
- **不得手改** `raw/` 下的任何内容 —— 需要更正时，改整理层并注明「原文如此，此处更正」。
- ★ **唯一例外：密钥脱敏（安全 > 逐字）** —— `raw/` 的产物由导出器写出时，会把**密钥字面量**替换成
  `<REDACTED:TYPE abcd…wxyz>`。这是**明知违反「逐字」但仍必须做**的一条：
  - **为什么必须做**：2026-10-19 用户在对话里粘贴了一个 GitHub PAT，导出器原样写进 `ai/raw/` 并进入本地提交，
    首次 `git push` 被 GitHub 的 **push protection 以 `repository rule violations` 拒绝** —— 即密钥真的进了仓库。
    若不脱敏，要么推不上去，要么把可用凭据公开到互联网。
  - **脱敏规则是确定的、单一的**：只做字面量替换，保留前后各 4 位便于人辨认；**不删除整段、不改其他字符**。
  - **因此「逐字」的准确表述是**：`redact(会话原文) == ai/raw 分片正文`，
    而**不是**「会话原文 == 分片正文」。`ai/tools/verify_raw_match.py` 就是按这个等价关系判的，
    并且**已用负对照验证过**：把一个普通字符改掉，判据照样翻红 ⇒ 脱敏不会掩盖真实差异。
  - **覆盖的密钥类型**：GitHub token（`ghp_`/`gho_`/`ghu_`/`ghs_`/`ghr_`/`github_pat_`）、AWS AK、`sk-` API key、
    Slack `xox*`、Google `AIza`、PEM 私钥头。**规则三处同源**（导出器 / 汇总器 / 校验器），改一处必须改三处。
  - ⚠️ **同族操作提示**：往对话里粘贴凭据，就是往记录里粘贴凭据。**用完请立即在服务端 Revoke。**
- **不得编造**：会话、日期、模型 ID、决策、原文位置，**一律以实际发生的为准**。宁可写「本轮未记录」，不写看起来完整的内容。
- **`discussing` 状态下不得动实现**：见 [`coordination/README.md`](coordination/README.md) 的硬规则。
- **一段会话只记一件事**（粒度过粗无法提炼技能包）；**边做边记**（事后补记等于伪造）。
- 本目录**不写** `log/user/`（若后续引入双份日志）：人那份**只能人写**，AI 不得代笔。
