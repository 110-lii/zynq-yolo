## 内容

| 路径 | 说明 |
|---|---|
| `YYYY-MM-DD_<短ID>.md` | 一个会话在某一天的逐字原文（跨零点按天切分，轮次号**不重置**，便于分片间对照） |
| `_prompts_all.md` | 全部会话的**用户提示词汇总**（按日期分组），由 `prompts_index.py` 从**全部分片重建**，不是某次运行的增量 |
| `README.md` | 本文件 |

**文件名规则**：`日期_短ID.md`，纯 ASCII。短 ID = 会话 UUID 前 8 位（`session-<uuid>` 取第一段）；
IM 派生 ID 用 `im_<sha1 前 5 位>`，子 agent 会话用 `dsh_<sha1 前 5 位>` —— 避免同前缀撞名。
**会话标题里的中文不会进入文件名**（脚本只从会话 ID 派生名字），故本目录无中文名文件。

## 分片内部结构（只看这 4 处即可判读）

| 位置 | 内容 |
|---|---|
| 文件头表格 | 会话 ID / 短 ID / 类型（主会话 or 子 agent）/ 模型 / 工作目录 / 时间 / **各类发言条数** / **已剔除项逐项计数** / **未导出项声明** |
| `## 轮次 N — 👤 用户` | **人类发言**：`prompt`（界面上真的打的字）与 `answer`（对 `ask_user_question` 的回答）共用此标题，靠 `<sub>` 里是否含 `ask_user_question` 区分 |
| `## 轮次 N — 📨 委派提示词 / 团队消息` | **非人类**：父 agent spawn 时注入的委派提示词、其他 agent 经 `send_message` 转发的团队消息。**不计入** `_prompts_all.md` |
| `### 🤖 模型回答` | 模型正文（逐字）+ 折叠的「思考过程（reasoning）」+ 折叠的「本轮调用工具 N 次」（单行摘要） |

> ⚠️ 正文的代码围栏长度**不是固定三反引号**：若某条消息自带 ``` 行，导出器会把围栏加长
> （正文内最长反引号连串 + 1），否则围栏会被提前闭合、正文被截断。**读/解析时用
> `(`{3,})` + 反向引用配对**，不要写死 ``` —— 实测一条 15 868 字符的团队消息曾被截成 1 802 字符。

**未导出**（文件头会声明，不是遗漏）：工具结果正文（`ask_user_question` 的用户回答除外）、
工具调用参数全文（折叠为单行，超 160 字符以 ` …` 结尾）、`system/message` 与注入上下文正文、附件二进制。
需要时按文件头给出的源文件路径取 `session.v4.jsonl.zstd`。**不做任何编造性补写。**

## 规则

- **不得手改**（`../README.md` §1.1）：一旦有人手改，「逐字」这个全称断言当场变假，且不会有任何东西报错 ——
  所以另配了 [`../tools/verify_raw_match.py`](../tools/verify_raw_match.py) 做**逐字节回比**，手改必被发现。
- **行尾必须是 LF**：本目录全部 `*.md` 的字节里**不得出现 `\r`**。
  `.gitattributes:13` 的 `* text=auto eol=lf` 会把 CRLF 在 `git add` 时规范化成 LF，
  于是「仓库里存档的副本」与「导出器写出的文件」不再逐字节相等 —— 而**逐字节比对本身发现不了**
  （`read_text` 的通用换行会把两边都翻成 `\n`）。故 `verify_raw_match.py` 另有一条**行尾审计**，
  任一 CRLF 即报 `VERIFY_EOL_FAIL`。导出器已强制 LF，**处置一律是重跑导出，不要手改、也不要改 `.gitattributes`**。
  原理与验收判据见 [`../tools/README.md`](../tools/README.md)「行尾必须是 LF」。
- **不得选择性取证**：同一工作区下的全部会话都导出（含「非本轮」的其它会话线程），
  `--list` 里的「本轮 / 非本轮」只是检索标记，**不是**导出筛选条件。
- **要更正就改整理层**并注明「原文如此，此处更正」，**不要回头改分片**。
- **定期重跑**：平台会话记录只保留有限天数；换客户端会**静默断链**（原文停更而无人发觉）。
- 命名硬约束（§1）：本目录新增文件名纯 ASCII、小写下划线。

## 怎么用

```powershell
# 1) 重新生成全部原文（会在本目录写入/覆盖分片）
D:\python\python.exe D:\zynq-yolo\ai\tools\export_transcript_dsh.py

# 2) 证明分片与原始会话逐字节一致（**导出后必跑**）
D:\python\python.exe D:\zynq-yolo\ai\tools\verify_raw_match.py --show
#    期望末行：VERIFY_RAW_OK（会先打印「行尾审计」段：每个文件 CRLF=0 裸CR=0）

# 3) 给人看「用户到底说过什么」（汇总，逐字）
Get-Content D:\zynq-yolo\ai\raw\_prompts_all.md

# 4) 从整理层回查某句话的原文位置
#    在 ../sessions/ 找到「原文位置」字段 → 到本目录对应分片按「轮次 N」定位
```
