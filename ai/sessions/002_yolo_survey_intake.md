## ★ 安全事故：明文 token 进了仓库，push 被 GitHub 拦下

| 项目 | 内容 |

| **怎么改**（修正动作） | ① 导出器加 `redact_secrets()`，放在**唯一出口**（`render_session` 的 return），保证没有路径能绕过；② `prompts_index.py` / `verify_raw_match.py` **同源复制**同一份规则表（三处必须同步）；③ **重新定义「逐字」的准确含义**：`redact(会话原文) == 分片正文`，并在 `ai/README.md` / `ai/raw/README.md` 写明这是**安全 > 逐字的唯一例外**；④ 校验器改为按该等价关系判，并打印「已脱敏后比对 N 条」；⑤ **`git reset --soft` 撤掉含密钥的提交 → 重新导出 → 重新提交**；⑥ `git reflog expire --expire=now --all` + `git gc --prune=now` **物理清除泄露 blob** |

## 结论与沉淀

**可用结论（带数字）：**

- **XC7Z020 上没有 Vitis AI DPU**：DPU-PYNQ 支持表 21 块板全为 UltraScale+/RFSoC/Versal，README 原文限定 「PYNQ-enabled Zynq Ultrascale+」⇒「7020 + DPU + model zoo」这条路**不存在**。
- **同芯片实测锚点**：ARC2020 在 XC7Z020 上跑 YOLOv3-tiny @416×416 / 16-bit 定点 = **532 ms（1.88 fps）**，
  用 **160 DSP / 185 BRAM18 / 25.9k LUT / 46.7k FF**，10.45 GOPS，3.36 W，mAP 30.9% vs 33.4%。
- **ARC2020 自己放弃了 8-bit**（某些层 8-bit 权重损失 **70.91%**）⇒「换 INT8 就能快一倍」是**待实测假设**，不是已知结论。
- **YOLOv3-tiny 的权威量（Lead 三算定型，与论文反推吻合到 0.1%）**：可训练参数 **8 856 570**（w+BN+bias）；
  **INT8 = 8.857 MB**（INT16 17.713 MB / FP32 35.426 MB）；**2.7825 GMAC = 5.5650 GOP/帧**；
  与论文 `10.45 GOPS × 0.532 s = 5.5594 GOP` 比值 **1.0010**。
  ⇒ **INT8 权重是板载 BRAM（4.9 Mb = 0.613 MB）的 14.5 倍**，「放不进片上」从「量级推断」升级为**有算式支撑的结论**。
- 从 ARC2020 到本仓库板卡（`xc7z020clg400-2`）**同芯片**；峰值算力：100/150/200 MHz ⇒ **44 / 66 / 88 GOP/s**。
  实测 10.45 GOPS 相对 150 MHz 峰值为 **15.8%**，但相对 ARC 自己的 160 DSP@100 MHz（32 GOP/s）为 **32.7%** ⇒ **引用「16%」必须写明分母**。
- ★ **两条被否掉的常见说法**：①「YOLOv3-tiny 权重 5.6 MB」是**把 GOP 数错标成 MB**；②「320 分辨率能到 20 fps」——
  YOLOv3-tiny 在 320 上是 **≈3.2 fps**，20 fps 属于**另一个更小的模型**（YOLO-Fastest 级）。**不能靠改分辨率达成 20 fps，只能换模型。**
- **跨会话交接的可用做法**：`session_search` 找到产出会话 → 从事件里读**确切文件路径** → 直接 `read` 磁盘文件。**不要靠时间阈值猜**。
