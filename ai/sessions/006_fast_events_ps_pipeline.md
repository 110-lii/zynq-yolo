## 球判别器（人工标签只有 5 个真球）

两批人工标注（200 + 100 张候选 ROI，来自全画面白块）只得到 **5 个真实球**，且来自同 5 帧；
其余是比分牌/广告牌/转播 UI。用这 300 个标签量出筛子：

- `草地环绕 >= 0.6` + `score >= 1.8` + `最大边 <= 30 px` ⇒ 40 个候选里 5 个是球（12.5%，原始 2.5%）。
- 接回板端：`ball_frames` 66/149 → 40/149，速度不变。

因真球太少，改用**合成正样本**（真实草地上渲染 4–16 px 白球，带阴影/模糊）+ 290 个真实负样本
训练 L2 逻辑回归（16x16 灰度 + 饱和度/亮度/填充率/尺寸，262 维）：

| 指标 | 值 |
|---|---|
| 真球留一召回（阈值 0.30） | **5/5** |
| 留出集真实负样本误报 | **1.3%（1/76）** |
| 真球只有 | 5 个 ⇒ 置信度低，不能当准确率 |

板端（带判别器，320x180 + 10 ROI + 补偿）：**64.8 ms / 15.4 FPS**，`ball_frames` 13/149，
`out_frames` 0（球很少，出界不再乱报）。

## 球员闸门（YOLOv8n 离线蒸馏）

板上实测 OpenCV HOG 行人检测 320x180 要 **219 ms 且 0 检出**；64x128 HOG 特征 5.2 ms/ROI，
10 个 ROI 就 52 ms，均不可用。改为 24x48 灰度 + HSV 直方图的线性模型（板上 0.2–0.5 ms/ROI），
标签由 YOLOv8n 离线生成。第一版用标准人框训练（AUC 0.900），但推理输入是运动块，分布不一致
⇒ 10 个候选只剩 1 个；改为**用运动块本身训练**（YOLO 给运动块打标签）后：

| 指标 | 值 |
|---|---|
| AUC（按片段留出） | 0.856 |
| 精确率 / 召回率 | 0.628 / 0.868 |
| PC 管线球员数（中位） | 3（原始运动块 10） |
| 板端双闸门（150 帧） | **81.3 ms / 12.3 FPS**；球员 3，球 13/149 |
| 球员闸门单 ROI | 3.8 ms（板端，10 个 ROI 共 38 ms） |

## 结论

1. **速度路线只能走 PS 像素管线**：CNN 引擎（PL）整帧 20.8 s，和 16 FPS 差 3 个数量级；在速度优先下 PL 暂时不参与，DDR 由 PS 帧缓冲使用。
2. **球员**：运动块 + 最近邻关联，320x180 每帧约 10 个候选；倒地用“框宽/高 + 高度相对中位数下降”判，原型 149 帧里触发 5 帧（未做人眼复核）。
3. **球**：白块 + 圆度 + 低饱和 + 草地环绕 + “不在球员框内”，149 帧里 66 帧有候选（44%），但仍无真值可评估；出界标志 44 帧，明显不可信。
4. 因此“速度可行”已被实测证明；**“识别率”没有过关**，尤其球。

## 未决问题

- 球没有真值：人工标注只得到 5 个真球（两批重复），合成正样本的判别器留一 5/5、误报 1.3%，但样本量不足以支撑“准确率”。
- 出界需要场地标定（单应矩阵或四点多边形），且球必须是**被跟踪的同一个球**，当前单帧候选不满足；固定机位 vs 跟拍尚未确认。
- 倒地判据未做人眼复核。
- PL 若要参与，合适的块是流式帧差/阈值/连通域（不是 CNN 引擎）。

## 结论与沉淀

- 板端 PS 在 320x180 上的像素预算是 10–16 ms 量级，16 FPS 的整合原型已跑通并出视频。
- 下一步应把“球候选 → 球确认”换成可训练的极小分类器（8x8 灰度 + 颜色/圆度特征 + 逻辑回归），推理 <1 ms，速度不受影响。
