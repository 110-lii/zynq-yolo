# Session 012 — 球链路「丢失窗口按秒计」板上验收与否决

## 结论（先给结果）

`--ball-lost-sec 0.4` **实测通过机器判据，但人工抽查全部是假球 ⇒ 否决，不留默认。**

机器统计上球帧 144 → 182（+26.4%）、球权 48 → 48（不掉），
按 010 定的回滚判据本该「通过」。**抽查推翻了这个结论**：新增 38 帧里
随机抽 3 帧（20 / 30 / 45），红圈位置**都不是球**。

## 怎么发现的

1. 板上跑 `check_board_acceptance.py`（本次新增），三组同一片段同一标定：
   `ball_clip.mp4` + `data/calib/field_calib_ball.json`，202 帧，`--every 25 --ball-every 2 --max-det 0`
2. 结果：base 144/48、lostsec 182/48、predict 144/48 → `BOARD_ACCEPTANCE_OK`
3. 按判据本来收工，但新增 38 帧的**坐标**露出破绽：
   帧号 20–57 连续，x 跨 **0.43 m**、y 跨 **0.36 m** —— 比赛进行中球不可能 1.5 s 不动
4. 用 `field_calib_ball.json` 的 H 逆变换把球场坐标投影回画面，抽 3 帧画圈导出 →
   帧 20 曾在白衣球员脚下（疑似真球），帧 30 / 45 圈内是空草皮；用户复核：**都不是球**

## 根因

不是「丢失窗口太短」，是**候选质量**：白块法会命中的静态白块（场地标线/广告/看台）
在放宽 `max_miss`（4 → 10）后黏得更久，假轨迹存活时间被拉长。
010 那两次 backfill 失败（球帧骤降、球权归零）与本轮（球帧虚增、球权不掉）
是同一个病根的两个方向：**容忍度参数治不了候选质量**。

## 判据教训（写进纪律）

- **机器统计不能单独作准**：球帧数上涨必须配人工抽查，否则「+26.4%」这种数字直接误导决策。
- 新增帧要先看**运动学**：连续帧位移接近 0 且非死球状态 ⇒ 先怀疑假目标。
- 验收脚本应内置这条：把「连续 N 帧位移 < 阈值」列为可疑并强制人工复核，而不是只比总数。

## 未决

- `--ball-lost-sec` 保留为**默认关闭的实验开关**，文档写明本轮否定结论，不再当候选方案；
- `--ball-predict-past-boundary` 在本片段触发 0 帧，**未被覆盖**，等有越界场景的片段再验；
- 真正该做的是候选质量（运动约束 / 静态白块抑制），需要一个「连续 N 帧位移 < 阈值即停跟并判可疑」的判据，
  以及一个能把可疑帧批量导出的复核工具——两者都还没做。
