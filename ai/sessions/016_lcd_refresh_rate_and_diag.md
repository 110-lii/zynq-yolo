## 结论

**LCD 的读数通路没问题，错的是像素时钟。** 25 MHz ⇒ 1056×525 下只有 **45.1 Hz**，
这块屏（ST7262）是**按 60 Hz 设计**的。改成 **33.333 MHz（实测 33.356，60.13 Hz）** 后，
地址扫描线性覆盖全部 480 行、像素数据恢复为真实 1bpp。
**人眼终验未做**（用户当时未回看），机器判据见下。

## 本轮改动

1. **LCD 独立 MMCM**：`clk_wiz`（VCO 750）out3 = 50 MHz → `clk_wiz_lcd`（VCO 1000，÷30）= 33.333 MHz。
   为什么不塞进同一个 clk_wiz：750 ÷ 33.333 = 22.5 非整数。
   为什么不两个 clk_wiz 都挂 `sys_clk`：同一引脚会被插两个 IBUF（oi 项目 Place 30-602）。
   同步改 `rst_lcd` 的 `dcm_locked` → `clk_wiz_lcd/locked`、`slowest_sync_clk` → 新 pclk。
2. **第二个 AXI GPIO（`0x41210000`）接 LCD 内部状态**：`dbg1={7'b0,lcd_de,pixel_data}`、
   `dbg2={10'b0,v_cnt,h_cnt}`。`lcd_status_top` 早就有这两个口，此前只接了 HDMI 那一路。
3. **`lcd_fb_reader.v` 恢复真实像素**：文件在 11:38 被写入了地址配色诊断
   （`bram_addr < 3000 → 红` 等），诊断留下了、屏幕就成了「四条横彩条」。
   现已恢复 `pixel_data <= wq[xq] ? WHITE : BLACK`，行基址位宽的修复保留。

## 上板读数（本轮）

```
MEM lcd_ctrl 0x40020000
DBG_DE duty=0.750            # 单行占空 800/1056=0.758，采样偏内
DBG_H min=0 max=1052         # h_total 1056，在走
DBG_V min=282 max=462        # v_total 525，持续递增
DBG_PCLK 33.356 MHz          # 期望 33.333
DBG1 01101820:684 00101820:81 01ffffff:23   # 深蓝底色 + 少量白字
BLIT panel mismatch 0
STATUS_DISPLAY_LCD_BRAM 0x40020000 via PYNQ  # 板端渲染 3 帧写缓存成功
```

读 GPIO 的坑：AXI GPIO 输入口**没有跨时钟同步**，pclk 域信号直接进 AXI 域，
单次读会出现撕裂值（实测能读到 `0100ff00` 这种只用一半字节亮的假值）。
**必须连读两次、只取两次相同的样本**，否则会把撕裂值当成真像素去推断。

## 诊断实验（值得复用的一招）

把 `pixel_data` 临时换成按 `bram_addr` 分段的纯色（红/绿/蓝/白），屏上出现**四条等宽横带**
⇒ 地址序列线性覆盖了全部 480 行、没有纵向压缩，且四段长度一致说明行跨距（25 字）也对。
这一步把「扫描/寻址」与「帧缓存内容」彻底分开，比再拍一张内容图快。
诊断脚测完必须撤掉——本轮忘了撤，直接导致下一版屏上是彩条、白查一轮。

## 纪律

1. **改屏幕前先量像素时钟，不要先改图案。** 45 Hz 与 60 Hz 的区别在屏上表现为「几何全错」，
   和寻址错误长得一样。

   白耗一轮判读。
