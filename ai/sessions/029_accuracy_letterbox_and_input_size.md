## 轮次 1 — 「现在可以牺牲掉时间去换取识别率……做好当前的备份，测试继续跑」

**输入提示词（逐字）：**

```
现在可以牺牲掉时间去换取识别率，你现在去研究一下，做好当前的的备份，测试继续跑
```

**做了什么：**

- 备份：`build/backup_20261101_2330/`（`repo.bundle` 67 MB + 在用模型 + 三个脚本 + `README.txt` 记基线数字），
  并在 `1e0eea6` 上打标签 `backup-before-accuracy-20261101`。
- 训练：`student_640_ft`，40 epoch、640 输入，person mAP50 **0.841** / P 0.894 / R 0.762（val 800 张、7569 实例）。
- 导出：同一份权重分别导出 ncnn **320 / 480 / 640** 三档（`build/models/person_w05_{320,480,640}.{param,bin}`）。
- 度量：**不靠 mAP 说话，改走部署同路径** —— 用 `board_detect.detect()` 真实代码 +
  `build/_fake_infer.py`（PC 上冒充板端 `ncnn_infer`，解码/NMS 口径一致）+ val 前 100 张（470 个 person 真值框），
  conf 0.25、IoU 0.5，算「真值框被检出且 IoU≥0.5 的比例」。

**实测矩阵（部署路径，召回）：**

| 模型 | 输入 | 预处理 | 召回 | 相对当前 |
|---|---|---|---|---|
| `person_v8n25`（在板） | 320 | squash（旧） | **0.183** | 1.0× |
| `person_v8n25` | 320 | letterbox | **0.313** | 1.7× |
| `person_w05` 微调 | 320 | squash | 0.385 | 2.1× |
| `person_w05` 微调 | 320 | letterbox | **0.405** | 2.2× |
| `person_w05` 微调 | 480 | squash | 0.395 | 2.2× |
| `person_w05` 微调 | 480 | letterbox | **0.547** | 3.0× |
| `person_w05` 微调 | 640 | squash | 0.264 | 1.4× |
| `person_w05` 微调 | 640 | letterbox | **0.609** | 3.3× |

**结论：** 涨分的两大来源不是「分辨率」，而是 ①**神经网络看到的尺度与训练一致**（letterbox，不压扁），
②**权重本身在 640 下重训过**。单纯把 320 权重的输入调大反而掉分（同一批图的动态测量：
基线模型 320 / 480 / 640 的 letterbox 召回是 0.330 / 0.191 / 0.148），因为它在训练时没见过那个尺度。

**我的判断：** 采纳（预处理改 letterbox）；模型档位待板端耗时实测后再定。

**理由：** letterbox 是**零成本**改动（同样的输入像素数、同样的推理量），实测在同一份权重上普遍 1.3–2.3×；
而换大模型是**成本**改动，必须先用板上的 `INFER_MS` 换算出帧率代价才能拍板。

## ★ 自我纠错轨迹

| 项目 | 内容 |
|---|---|
| **错在哪**（原始判断） | 以为「同一份 ncnn 模型可以喂任意边长」—— 早先的记录里写过「三处尺寸必须一致」是对的，但没意识到**导出时输入尺寸被烧进 param**，一个模型只能跑它导出的那个边长。测矩阵时先拿 640 模型喂 320，得到 `召回=0.000`，一度以为是精度崩了。 |
| **怎么发现**（触发条件） | `0.000` 太整齐：squash/letterbox 两种预处理都精确是 0，不像「检不到」，像「没跑起来」。查 `_fake_infer.py` 的 `EXTRACT_FAIL` / `INPUT_FAIL` 分支才对上：喂 320 给 640 模型时 ncnn 直接报输入尺寸不符。 |
| **证据** | `build/_e2e_matrix.py` 输出：`M 640微调 size=320 letterbox 召回=0.000`；同样权重导出 320 后同一组图片 `召回=0.405`。`model.ncnn.param` 首行后可见静态 `Input ... 2=640 3=640`。 |
| **怎么改**（修正动作） | 把「一模型一尺寸」写进 `board_detect.detect()` 的 docstring；为微调权重**分别导出 320/480/640 三份**，文件名带尺寸（`person_w05_{320,480,640}`），避免再拿错。 |
| **判据**（怎么确认改对了） | `build/_e2e_matrix.py` 的 8 行里，只有「模型导出尺寸 == size 参数」的 4 行非零，其余全 0；且 nonzero 的 4 行与更早的 ultralytics 动态尺寸测量（0.396/0.544/0.597）吻合到 ±0.02。 |
| **根因归纳** | 静态图导出把尺寸固化，而「模型」「预处理」「调用参数」分散在三个文件里，**没有一个地方强制它们相等**。这类错误不报错、只表现为精度归零 ⇒ 必须靠「导出文件名带尺寸 + 运行时答非所问即报错」双重约束。 |

| 项目 | 内容 |
|---|---|
| **错在哪**（原始判断） | 写自检脚本时把 squash 路径的期望值写成 `y=360`（凭直觉「720 的一半」）。 |
| **怎么发现**（触发条件） | 自检直接 FAIL：实际 `202.5`。 |
| **证据** | `build/_letterbox_check.py` 首次运行：`FAIL squash 逆变换 y=360 202.5`。 |
| **怎么改**（修正动作） | 期望值改为 `90 × 720/320 = 202.5`；自检全绿 `LETTERBOX_CHECK OK`。 |
| **判据**（怎么确认改对了） | 同一脚本 9 项全 PASS，且 `squash 无补边`（整幅 200 灰）与 `letterbox 上下各 70 行 114` 两条互斥成立。 |
| **根因归纳** | 手算期望值时把「网络坐标」和「原图坐标」混在一起（90 是网络坐标，不是原图 y）。逆变换类代码必须**用一组能整除的数**写期望值并同时断言正反两个方向。 |

## 结论与沉淀

**可用结论（带数字）：**

- 部署路径上，同一份模型只把「压扁」换成「保比例补边」，召回从 0.183 → 0.313（1.7×），推理量不变。
- 换 640 重训权重 + letterbox@640，召回 0.609，是当前在板配置的 3.3×，代价是约 4 倍算力（未在板上实测）。
- ncnn 导出的模型**只能在导出尺寸上跑**；换尺寸必须重新导出。

**可沉淀为技能包的内容：**

- [ ] → `../../skill/`：**「静态图模型换尺寸必须重新导出」**的踩坑条目（症状：召回精确为 0；判据：param 里的 Input 尺寸与调用参数一致）
- [ ] → `../../skill/`：**「预处理必须与训练一致」**的度量模板（固定同一份权重，只改预处理，出对照表）
