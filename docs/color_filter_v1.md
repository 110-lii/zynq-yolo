# 球衣颜色筛人（v1）—— 从 `person` 里分出球员 / 非球员

> 决策依据：**D012**（球员/非球员区分是球权判定的前置依赖）、**D013-a**（颜色是用来「更好地识别球员」，不是给框染色）。
> 工具：`tools/player_color_filter.py`。本文件记录**做法、实测数字与已知失效**，不写「应该能」。

## 1. 为什么不用「固定调色板 + argmax」

首版做法：把躯干 HSV 与 `classify_players.PALETTE_REF` 逐一比距离，取最像的颜色，颜色属于两队就留。
在 inc_12 第 60 帧上它把 **4~5 个红队球员判成「黄色裁判」剔掉**了 —— 转播暖光下红队球衣的中位色相
漂到 30~37°，而黄色裁判标定在 28°，两者只差几度。固定调色板 + argmax 在光照漂移下不可用。

现在的做法是三层：

| 层 | 判据 | 作用 |
|---|---|---|
| ① 位置 | 框**脚底**落点是否在草皮掩膜内（`ball_cv_probe.grass_mask`，±6 px） | 剔除看台观众、场边工作人员。**色彩回答不了「人在不在场上」**：穿白 T 的观众和白队球员颜色一样 |
| ② 颜色 | 用本帧**高置信**（≥0.35）检测的躯干中位 HSV 做 2-means，得到两队颜色中心；逐框按归一化 HSV 距离归到最近中心 | 自适应光照与脏球衣，不用预设色名；离两中心都远（>0.75）才算非球员 |
| ③ 补检 | conf 0.25→0.12 的低置信框，只要颜色归队、脚在草上就保留 | 找回远景小目标（D013-a 的「补检」） |

无彩色单独处理：白/黑球衣的色相是噪声（实测白队 H 在 48~90 之间乱跳），
所以任一侧 S<0.22 时**只比 S/V，不比色相** —— 否则白队整队被判「离中心很远」丢掉。

| 380 | 16 | 14 | 1 | 2 |

人眼核对两帧（f60 / f300）：保留框都落在球员身上，**没有再把红队当裁判剔掉**。

## 2.1 门将（2026-10-27 补）

首版把门将当「离两队都远」剔掉了（f300 右上角深色门将）。现在：
- `tools/match_setup.py` 的配置里 `teams.A/B.keeper_color` 可空填门将球衣色（可选字段，向后兼容），
  CLI 是 `--keeper-a/--keeper-b`；
- 筛人时**先判门将**（阈值放宽到 0.30：门将服常是深色/荧光色，与调色板参考值差得远，
  实测那件深色门将 sc=0.32，用 0.45 判不出来），命中就保留，标签写成 `GK:<颜色>`。

实测（inc_12 f300/f340/f500/f560）：门将 1~2 个/帧被正确保留，裁判 1 个/帧被剔除。

## 3. 已知失效（不许在报告里说成「已解决」）

2. **近景/无草皮镜头**：位置判据会把该帧所有人都剔掉（f640：5 框→0）。近景本来也不该做场上判定，
   但要显式输出 `no_pitch` 状态，而不是静默返回空。
3. **白色队服 vs 白色广告牌**：躯干区域若被广告牌切进来会拉低可信度；目前靠脚底位置兜底。
4. 只看**单帧**：没有跨帧一致性（一帧判 A、下一帧判 B 的情况没有惩罚）。跟踪层的队别平滑未做。
5. **门将颜色仍要人来填**：不填就回到旧行为（门将被剔）。自动从「球门区 + 非两队色」推门将未做。

## 4. 用法

```bash
py tools/player_color_filter.py --selftest
py tools/player_color_filter.py --video data/samples/incidents/inc_12_t06867.9.mp4 \
    --frames 60,300 --team-a white --team-b red --ref yellow --imgsz 1280 --adaptive \
    --viz-dir <输出目录>
```

`--team-a/--team-b` 只作为 2-means 的初始种子；颜色最终以本帧统计为准。
**本工具尚未接进 `board_pipeline.py` 主线**。代价已在本机量过：4 帧、平均 21 个框，
筛人 **7.61 ms/帧**（0.36 ms/框）。板上 A9 会慢若干倍，但相对检测（0.95~1.0 s/帧）仍是小头；
**仍需板上实测后再决定默认开关**。
