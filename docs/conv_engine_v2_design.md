## 1. 方案里可直接采纳的部分

1. **100 MHz 作为基线时钟**（§7.4/§13），125 MHz 作为上限尝试。
2. **资源红线**（§8.1）：LUT ≤42k、FF ≤65k、BRAM ≤120、DSP ≤150；LUT 超 85% 即停。
3. **共享加速器、一次调用跑整网**（§7.4）：把 60 次 PS 调用改成"PS 启动一次 + PL 内部
   逐层推进"，用片上微码/描述符表描述层序列。
4. **DMA + 双缓冲/环形缓冲、零拷贝**（§14）：输入输出用连续物理内存，避免每层重设指针。
5. **PL 预处理**（§7.2）：YUV420→RGB、Resize、Normalize 搬进 PL，PS 只做调度。
6. **球员单类 + 足球 ROI 两级检测**（§9）：模型层面把 0.944 GMAC 降到约 0.05–0.1 GMAC。

## 2. 时钟

**目标 100 MHz（方案基线），最高试 125 MHz。**

现状关键路径 10.41 ns（83.33 MHz 下 WNS +1.588 ns）⇒ 上限约 96 MHz：

```
DSP48E1(row_byte_2_reg) → gmem_r_addr[59]/CE
```

改法：

1. `row_byte = (ci*H_IN + hr) * W_IN` 改为**增量累加**（`base += H_IN*W_IN`），乘法移出地址路径；
2. requant 的 48×48 乘法加一级流水（旧版 100 MHz −1.247 ns 的来源）；
3. 先出 100 MHz；WNS ≥ +1.5 ns 再试 125 MHz。

## 3. 加速器结构（对齐方案 §7.4）

### 3.1 现状问题

PS 每层调用一次 IP：60+ 次/帧，每次都要写 5 个指针 + 11 个标量 + 轮询 ap_done。
实测 1.45 s 的"其他"里，很大一部分是这部分开销与非卷积算子。

### 3.2 改法：片上层序列

- 新增 **layer table**（BRAM，≤64 项 × 32 B）：每项存 {输入偏移, 输出偏移, C_IN, C_OUT,
  H, W, K, stride, pad, zp_in, zp_pre, 权重偏移, params 偏移, lut 选择}。
- PL 侧一个 `layer_seq` 状态机：按表逐层启动 conv_engine，层间只切地址，不回到 PS。
- PS 每帧只做一次：`ap_start` + 等待完成 + 读检测输出。
- 非卷积算子（BN 已融合、SiLU 走 LUT、上采样/Concat）分两类：
  - 能折进 conv 的（BN/SiLU）已在 LUT 里，不动；
  - 上采样/Concat/Pool 用小的 PL 模块，或保留 PS 但按层批量处理。

**收益**：消掉 60 次 MMIO/轮询，给 ping-pong 提供连续的数据流。

## 4. 访存（在现有实测基础上）

| 项 | 改法 | 依据 |
|---|---|---|
| 权重布局 | 每 (co,ci) 补齐到 12 B，读 3 个对齐字、静态取字节 | 事务 72→24/ci |
| 读口 | 输入 / 权重拆两个 bundle → HP0 / HP1 | 单口 222 MB/s，双口 444 |
| 重叠 | 输入行缓冲 + 权重缓冲双份，load(ci+1) 与 compute(ci) 并行 | 每 ci ~100→~45 拍 |
| 输入重复读 | 本版不做；等前三项落地再评估 | 最多 8× |

## 5. 资源预算（按方案 §8.1/§8.2 收紧）

| 模块 | 方案预算 LUT | 现状 LUT | 处理 |
|---|---:|---:|---|
| 共享 CNN 加速器 | 20k–30k | **39.4k** | 必须降：TILE_W 40→32、输入解包改 2 字节/拍 |
| DMA/控制 | 4k–6k | — | 新增 |
| 预处理 | 4k–7k | 0（在 PS） | 新增（第二阶段） |
| 合计上限 | **42k** | 39.4k 已占满 | 不降引擎就没有余量做 DMA/预处理 |

**硬约束**：v2 的 conv 引擎必须 ≤30k LUT，否则第 3 节的层序列和预处理都放不下。

## 6. 分阶段（每阶段都可单独验证）

| 阶段 | 内容 | 预期 |
|---|---|---|
| A | 时钟 100 MHz + 地址/requant 流水 | 整网 9.63 → ~8 s，WNS > 0 |
| B | 权重 12 B 对齐 + 双读口 | conv 8.1 → 4–5 s |
| C | ping-pong 重叠 + 引擎瘦身到 ≤30k LUT | conv → 2–2.5 s |
| D | 层序列（一次调用跑整网） | 去掉 1.4 s 的 PS 开销 |
| E | PL 预处理（YUV→RGB/Resize/Normalize） | 再省 ~160 ms/帧 |
| F | 换模型：球员单类小网 + 足球 ROI 网 | **5–10 FPS 的唯一路径** |

A–C 是对现有引擎的改造；D–F 是向方案靠拢的结构性工作。

---

## 7. 必须说清的问题

1. **模型是最大变量**：完整 YOLOv5n 是 0.944 GMAC/帧；方案建议的球员单类小网约
   0.05–0.1 GMAC。即使加速器做到 64 MAC @125 MHz（8 GMAC/s 峰值、按 30% 效率 2.4 GMAC/s），
   完整 YOLOv5n 也要 ~0.4 s，单类小网只要 ~0.04 s。**不换模型，5–10 FPS 不可能。**
2. **LUT 已经顶到方案给整块 PL 的上限**：39.4k/42k。继续加功能前必须先瘦身。
3. **层序列/ DMA 是接口级改动**：要同时改 IP、BD、PS 驱动、stream pack，风险高于 A–C。
4. **每轮约 1.5 小时**（综合 46 min + 出片 8 min + 板测 10 min）。
