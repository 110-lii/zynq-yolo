# 球员判定门控层 v2（D013-a 的收口点）

> 工具：`tools/player_gate.py`　机读结果：`data/results/player_gate.json`
> 上游依据：[`hi_layer_color_gate.md`](hi_layer_color_gate.md) §6（第二批 159 框分层判决）
> 上游依据：[`color_prior_v1.md`](color_prior_v1.md)（颜色作为手段的四条用法）
> 决策：**D013-a**（颜色是用来「更好地识别球员」的手段，不是给框染色）

---

## 0. 这份文档回答什么

`hi_layer_color_gate.md` §6 只用**层间相对高低**说了一件事：hi 层取色失败的四类原因里，
非球员率差 9 倍（purity 97.4% / rect 67.6% / color 43.6% / too_small 12.9%）。
「差 9 倍」到「该怎么门控」中间还有一段：**哪一层丢、哪一层留、哪一层降权，
以及丢了之后代价是什么**。本文件就是那段，并且**每一组都带可复算的对照**。

一句话结论：**按原因门控在 12 段全量上只丢 98/12 585 框（0.78%），
而 v1（取不到色就丢）丢了 834 框且其中 88.2% 是被误伤的球员**——
所以「颜色取不到 ⇒ 非球员」这个方向从一开始就是错的，v2 靠几何守卫与 hull 复核把这条翻过来。

---

## 1. 规则表（三件事，不是一件事）

门控不是「规则表」单打独斗，**规则 + 几何守卫 + hull 复核**三层同时生效，缺一层就退化成 v1：

| 层 | 判什么 | 取值 |
|---|---|---|
| ① 原因规则 | 取色失败原因 → 动作 | `too_small` → **keep**（小框看得见人，只是取不到色）<br>`purity` → **drop**（躯干里大部分不是球衣 ⇒ 广告牌/看台/背心）<br>`rect` → **drop**<br>`color` → **demote**（离两队都远，但离球员不远 ⇒ 降权不丢） |
| ② 几何守卫 | 位置/尺度是否像球员 | 场内判据 `FIELD_Y_MIN=0.35`；远端人群 `far_frac=5.0` 倍中位框高且 `far_abs_px≥160` ⇒ `far_crowd`（v2 只 demote，不丢） |
| ③ hull 复核 | 球衣色像素在其凸包面积里的占比 | `HULL_PURITY_MIN=0.60`，且面积占框 ≥ `HULL_MIN_AREA_FRAC=0.25` 才做（否则那是整块背景） |

判据口令（JSON 里 `params.rules` 可核对）：`too_small:keep / purity:drop / rect:drop / color:demote`。

## 2. 八组消融（同一批 12 段、12 585 个 hi 框、1 110 个处理步）

`data/results/player_gate.json` → `ablation`。**判据全部与标注无关**（位置/轨迹/conf/框高）：

| 组 | 保留 | 丢 | 丢弃率 | 保留框场内率 | 丢弃框场内率 | 差 |
|---|---|---|---|---|---|---|
| `after`（v2） | 12 487 | **98** | **0.78%** | 97.57% | 78.57% | **−19.0 pt** |
| `legacy`（取不到色就丢） | 11 964 | 621 | 4.93% | 97.96% | 87.12% | −10.8 pt |
| `v1struct` | 12 475 | 110 | 0.87% | 97.57% | 80.91% | −16.7 pt |
| `norules`（关规则） | 12 585 | 0 | 0 | 97.43% | — | — |
| `noprior`（全 unknown） | 12 585 | 0 | 0 | 97.43% | — | — |

读法：**丢弃桶的场内率必须显著低于保留桶**，否则丢的就不是「场外的人」。
v2 的 −19.0 pt 是八组里最大的，且丢弃量只有 legacy 的 1/6。
（`nohull` −17.8 pt / 107 框、`nostruct` 与 `after` 同值、`minimal` 只打标签不丢框，
完整表见 JSON。）

## 3. v1 → v2：736 个被误伤的球员

`v1_vs_v2`：

| 项 | 数 |
|---|---|
| v1 丢弃 | 834 |
| v2 丢弃 | **98** |
| **被 v2 救回** | **736（88.2%）** |
| 仍被丢 | 98 |
| v2 **新增误杀** | **0** |
| 救回框的场内率 / 框高中位 / conf 中位 | 91.85% / 122.6 px / 0.574 |

救回机制分解：`color_demote_color` 442、`color_keep_too_small` 263、
`far_crowd` 12、`geo_rescue_purity` 11、`purity_hull_ok` 6、`colored_A/B` 各 1。

⇒ 两个最大的误伤来源是 **「color 层一律丢」** 与 **「too_small 一律丢」**，
两者合计 705/736。这两个恰好是「颜色取不到」与「人太小」——**都不是非球员的证据**。

## 4. 空间与场景切片（场内判据是不是一条拍脑袋的水平线？）

`FIELD_Y_MIN=0.35` 是一条水平线，画面深处草坪与看台会重叠，所以做了三种同向性检查：

| 检查 | 结果 |
|---|---|
| `by_band`（场内实心 / 容差带 / 场外实心） | 丢弃率 **0.63% / 6.73% / 8.00%**（单调递增，方向对） |
| `by_scene`（近景 / 远景 / 稀疏） | 丢弃率 **5.71% / 0.235% / 8.92%**；丢弃框场内率 78.7% / 59.3% / 100% |
| 三种场景判据（y_min / center / foot） | 差值 −19.0 / −23.5 / −14.8 pt，**同向** |

→ 门控没有只在「y<0.35 的那条线」上讨生活：远景组丢弃率 0.235% 说明它几乎不碰远处的人。

## 5. hull 纯度阈值（0.60）的敏感性 —— **尚未测量**

`HULL_PURITY_MIN=0.60` 是**按像素几何选的**（球衣色像素占凸包面积的比例），
**不是**从标注集拟合出来的（标注也不支持这种拟合：一致性尚未测量，见 §6）。
本文件**没有**给出「阈值 0.5 / 0.7 时丢弃数与场内率如何变」的扫描 —— 这是明确的缺口，
不是已经验过的结论。`tools/player_gate.py` 目前**没有** hull 阈值扫描开关
（`--ablate` 只跑固定八组），要做就得先补开关再引用数字。

## 6. ★ 诚实缺口（这些是「已知没做好」的，不是「没提到」）

`player_gate.json` 的 `gate_defects` 与 `precision_proxy` 里写着三条硬事实：

1. **`rect` 层几乎没起作用。** 标注说 rect 层 67.6% 是非球员（n=37），
   按抽样率折回盘面约 **656** 个非球员框，而门控只丢了 **11** 个（`real_recall_est=0.017`）。
   ⇒ 准确率上最大的漏网点在这一层，**不是 recall 问题**。
2. **`purity` 层仍保留了大部分。** 层内约 102 个估计非球员框，只丢 87 个；
   而保留下的 `geo_rescue_purity` 有 802 个框、场内率 100%、conf 中位 0.726 ——
   这批里有多少是裁判/教练，**没有标注能回答**。可证伪预测见 JSON：抽 20 个看跨帧稳定性。
3. **`color` 层一个都没丢**（v2 是 demote）。这是有意的：v1 正是「color 一律丢」伤了 442 个球员。
   代价是 color 层的非球员（估计约 38 个）留在了 unknown 里 —— 交给下游按 conf 排序处理。

此外：

- 所有指标都是**结构量**（位置/轨迹/conf/框高），**不能当 precision/recall**。
  `precision_proxy` 的 `real_recall_est_total≈1.17` 只读作「门控丢掉的数量级相当于估计非球员量」，
  不能读成「召回了 117%」——它自身带着「标注批与本次运行同分布」的隐含假设。
- 标注一致性**未测量**（第三批 60 框 `data/annot/labels3.csv` 还没标；标完跑
  `tools/repeat_agreement.py`）。所以层内 N 率只用于**相对高低**。
- 素材仅 12 段、同一场比赛、单机位、红/白队服；白队区分度天生弱。
  跨场表现见 [`cross_match_eval.md`](cross_match_eval.md) §12（新场 unknown_rate 20.6%→47.7%）。

## 7. 怎么复算

```powershell
$env:PYTHONIOENCODING='utf-8'
cd D:\zynq-yolo

# 全量八组消融（约 114 s）
D:\python\python.exe tools\player_gate.py --ablate --write
# 期望末行：PLAYER_GATE_OK <n_kept> <n_dropped> <metric> [CONFLICT=<n>]

# 把门控接到颜色先验主链路上（与 ② 去留只有一套说法）
D:\python\python.exe tools\color_prior.py --gate after
```

`tools/color_prior.py` 的 `--gate` 在 `tools/color_prior.py` 的 `_load_gate()` 里通过 importlib 加载本模块，
**显式把 `PALETTE_REF / color_of_name / torso_rect / classify` 换成同一份对象**——
两套阈值口径必须物理上是同一个对象，否则会出现「数值相等但语义不同」的静默分叉。
