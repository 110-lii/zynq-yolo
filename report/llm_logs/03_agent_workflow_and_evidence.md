## 1. 工作流：Lead 拆任务，子代理只写指定路径

会话 001 的任务口径逐字要求：

- 「必须**先读** `D:\zynq-yolo\docs\repo_spec.md`（命名规则 §1，职责 §2，§6 环境事实，§7 未决项）」；
- 「**只借鉴结构，不要复制旧项目的任何具体决策内容**」；
- 「**只登记已由用户明确裁定的两条**」；
- 「**不要编造不存在的会话**」；「**不得发明决策、会话或日期**」；
- 「**只写 `D:\zynq-yolo\ai\`**，其他成员在并行写别的路径」。

这形成了本项目的默认协作方式：

| 角色 | 职责 | 写范围 |
|---|---|---|
| Lead | 拆任务、冻结接口/口径、收口、最终验收 | 决策台账、跨目录收口 |
| 子代理 | 单点调查或实现，只改被指定的文件 | 任务描述里列出的路径 |
| 复核 | 只读审计，产出核验表与判据 | `.research/` 或报告草稿 |

**教训**：并行写同一文件是协作事故的常见来源；写范围必须**在任务里逐路径列出**，
而不是口头说“你负责文档”。

## 2. 证据纪律：数字必须能回指

会话 002 把“接收侧报告”变成仓库资产时，模型做了三件可复用的事：

1. **不采信报告自述**：论文锚点 `532 ms / 1.88 fps / 160 DSP / 185 BRAM18 / 25.9k LUT /
   46.7k FF / 10.45 GOPS / 3.36 W` 逐行核到 `.research/arc2020_paper.txt` 第 591–592、
   675、697–698 行；
2. **撤回无出处数字**：原报告“YOLOv3-tiny INT8 权重 ≈5.6 MB”与“5.6 GOP/帧”同值，
   疑单位串用，且本地证据未给 MB 数 ⇒ 撤回具体值、只留量级，并新增 §9 未验证项清单；
3. **机械对账而不是肉眼**：链接 `broken=0`、URL 集合差恰好 1 条、数值 token 无净减少。

**落到本仓库的规则**：

- 进入 `report/` 的每个数字，必须能指回 `build/reports/`、`board/logs/`、`data/results/`
  或 `ai/sessions/`；
- 查不到出处的数字**不写**，宁可留“未测量/未保留”；
- 报告里的“已知边界/未完成项”与“已完成结果”分开写，不把计划写成结果。

## 3. 自我纠错：三次真实事故

### 3.1 “最近没变”≠“不存在”

- **错在哪**：用“文件比某个时刻新”判断有没有新产物，门槛是凭印象定的 15:30；
- **怎么发现**：目标文件其实早已存在，只是修改时间早于该门槛；
- **怎么改**：先问“它叫什么名字”，再问“它什么时候写的”；用 `read` 成功返回全文作判据；
- **判据**：`read D:\zynq-yolo\.research\yolo_on_zynq7020_survey.md` 返回 164 行全文。

### 3.2 “逐字记录”把凭据也逐字存了

- **错在哪**：用户把 GitHub PAT 粘进对话，`ai/raw/` 是逐字转录，于是凭据被写进分片并提交；
- **怎么发现**：复核时意识到“逐字”与“凭据安全”冲突；
- **怎么改**：导出器在**唯一出口**加 `redact_secrets()`，三处规则同源；重新导出、重提、
  清理历史 blob；
- **判据**：`git grep` 0 命中；遍历全部 git 历史对象 0 命中；`verify_raw_match.py`
  `VERIFY_RAW_OK`；负对照（改一个普通字符）立刻 `VERIFY_RAW_FAIL`。
- **教训**：安全必须做在**写出端**，不能靠事后清理；默认开启、不可关闭。

### 3.3 “派了审计”≠“审计已完成”

- **错在哪**：以为派了独立 subagent 就等于核验完成；
- **怎么发现**：终稿文件不存在，结论无法引用；
- **怎么改**：把判据改成“终稿文件存在且结论可引用”，并把核验表（57 行：✅33/⚠️19/❌1/🔶4）
  落盘；
- **教训**：协作任务的完成判据必须是**产物 + 可复现判据**，不是“我说做完了”。

## 4. 自检门禁：`tools/check_repo.py`

`check_repo.py` 把“提交包边界”变成可执行判据：

- **检查范围** = `git ls-files --cached` + `--others --exclude-standard`（即 `git archive`
  的边界）；本机 venv、Vivado 运行目录、训练环境不参与，避免假 FAIL；
- a) 命名纯 ASCII；b) 必需目录/根文件；c) 每个目录有 README；d) 禁入文件；
  e) 评测权重一致性；f) 自有 `.py` AST 可解析；
- 成功判据是末行 `CHECK_REPO_OK`，不是退出码。

**为什么补 f)**：2026-10-19 一次批量编辑把 `sys.dont_write_bytecode` 插到
`from __future__ import annotations` 之前，4 个脚本语法错误，而 a)–e) 全绿。
**门禁绿灯不等于代码能跑**，所以新增源码解析检查；本次提交前实测
`SUMMARY: 6 PASS / 0 FAIL / 0 WARN`、末行 `CHECK_REPO_OK`。

## 5. 结论

- 智能体协作要**先定写范围与判据**，再并行；否则“完成”无法验收；
- 证据纪律不是写报告时才用，而是贯穿调查、实现、验收、沉淀；
- 最有价值的记录不是“模型答对了什么”，而是**“错在哪、怎么发现、怎么改、判据是什么”**。
