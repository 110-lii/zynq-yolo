## 技能包的四类形态（指南 3.3.5.2，可任选一种或多种）

| 形态 | 指南原文定义（`text 955-959`） | 本仓库落点举例（举例≠已有，勿当交付） |
|---|---|---|
| **提示词工作流** | 一组经过验证、能稳定完成某类任务的提示词模板及使用说明，例如从算法描述推导软硬件划分、根据综合报告定位瓶颈 | `<skill_name>/prompts/` + `README.md` 里的使用方法 |

## 每个技能包的强制结构（缺一节就不算技能包）

每个技能包目录**必须**含 `README.md`，且必须写清以下五节：

| # | 必须写的节 | 内容要求 | 依据 |
|---|---|---|---|
| 1 | **适用范围** | 什么器件 / 板卡 / 工具版本 / 题目形态下可用；边界在哪 | 指南 3.3.5.2「适用范围」 |
| 2 | **使用方法** | 命令级或步骤级，陌生人照做即可复现 | 指南 3.3.5.2「使用方法」 |
| 3 | **失效条件** | 什么情况下会失效（工具版本、器件、被绑定到本队题目…），失效时的**可观察现象** | 指南 3.3.5.2「失效条件」 |
| 4 | **提炼来源** | **从哪些失败或观察中总结得出**，并指出 `../ai/` 里的原始出处 | 指南 3.3.5.2「说明是从哪些失败或观察中总结得出」 |
| 5 | **已验证的效果** | 本队用什么判据验证它真的有效（判据要能失败，不要只写「好用」） | 指南 3.3.5.2「已验证的效果」 |

> 指南 3.3.5.3 第 6 项要求报告写出「技能包的提炼过程：从哪些失败或观察中总结、**如何验证有效**、**边界如何确定**」——
> 这三问正好对应第 3/4/5 节，因此**报告里写不出来的技能包，就是还没提炼好的技能包**。

## ★ 加分点：通用 PYNQ Skill 单独加分

> 指南 3.3.5.2 末段（`text 962-963`）原文：
> 「**通用 PYNQ Skill 单独加分。** 若提交的 Skill 面向 PYNQ 框架且**不与本队题目绑定**（换题目、换板卡仍可用），在本赛道评分中另行加分。」

因此本目录的**提炼优先级**是：

1. **先做通用 PYNQ 技能包**：面向 PYNQ 框架（Overlay 加载、`.bit`+`.hwh`、寄存器映射、DMA 与缓存一致性、上板体检与性能基线等），换题目/换板卡仍可用 ⇒ **额外加分**；
2. 再做与本队题目绑定的专用技能包（不计入该项加分）。

判断口径：**把本队题目整个换掉，这个技能包还能不能用？** 能 ⇒ 通用，进加分；不能 ⇒ 题目专用。

## 规则

- **命名**：目录名/文件名纯 ASCII 小写 `snake_case`，只用 `a-z 0-9 _ - .`（指南 3.3.5.4）；中文只出现在正文。
- **每包一 README**：技能包目录没有 `README.md`，或五节不全 ⇒ 不算交付。
- **不编造**：未经验证的技能、没出处的数字不得写入（承 `docs/repo_spec.md` §6/§7）。
- **失效条件要具体**：写「怎么发现的」（失败现象 + 排查步骤），不写「可能不适用」这类空话。
- **自检**：`python tools/check_repo.py` 会检查每个必需目录（含 `skill/`）是否有 `README.md`。

## 怎么用

```powershell
cd D:\zynq-yolo
python tools\check_repo.py                 # 仓库自检：目录 README / 命名 / 禁入文件
mkdir skill\<skill_name>                   # 目录名纯 ASCII 小写 snake_case
```

陌生人从零新增一个技能包：

1. 在 `..\ai\` 的过程记录里挑出一条**真实失败或观察**（先有原始记录，再有技能包）。
2. 新建 `skill\<skill_name>\`，写 `README.md`，五节齐（适用范围 / 使用方法 / 失效条件 / 提炼来源 / 已验证效果）。
3. 把可复用资产一并放进去（提示词模板 / 脚本 / 骨架 / 踩坑清单），保证**只靠本目录**就能用。
4. 回填上方「技能包清单表」，并判断是否满足「通用 PYNQ」加分口径。
5. 在 `..\report\` 里补写第 6 项「技能包的提炼过程」，与本节第 3/4/5 节逐条对应。
