# edge_infer_scale_ladder —— 边缘推理的输入尺度分档实验

> 上级：[`../README.md`](../README.md) · 类型：**通用技能包（不绑定足球题目，换模型/换板仍可用）**

## 1. 适用范围

- **运行环境**：CPU / PS 上的静态导出模型（本队实测 Zynq-7020 PS + ncnn fp32；同样适用于
  TFLite、ONNX Runtime 等「输入边长在导出时固定」的模型）。
- **任务形态**：已经有一个能跑的检测器，想分别量出「预处理方式」与「输入边长」各值多少分。
- **前提**：有一批带真值框的评测图（本队 100 张 / 470 个 person 框）和一条**能跑通部署代码**的推理路径。
- **不覆盖**：训练、量化、剪枝、动态 shape 模型；也不回答「换更大模型值不值」——那是成本项，
  要在本包之后用板端 `INFER_MS` 换算。

## 2. 使用方法

### 2.1 把两个变量拆开

一次只动一个变量，矩阵按 2×N 排：

| 变量 | 取值 | 说明 |
|---|---|---|
| 预处理 | `squash`（直接 resize 到正方形）/ `letterbox`（等比缩放 + 补边） | 后者不改变目标长宽比 |
| 输入边长 | 320 / 480 / 640 | 同一份权重分别导出，**文件名带尺寸** |

### 2.2 用部署路径评测，不用训练框架的 mAP

```python
# 伪代码：真实 detect() 全路径 + 与板端 C++ 同口径的替身
for size in (320, 480, 640):
    for lb in (False, True):
        hits = 0
        for img, gts in evalset:                 # 100 张 / 470 个真值框
            dets = detect(img, model=f"person_w05_{size}", size=size,
                          letterbox=lb, conf=0.25, iou=0.5)
            hits += sum(1 for g in gts if any(iou(d, g) >= 0.5 for d in dets))
        print(size, lb, hits / 470)              # 召回：真值框被检出且 IoU≥0.5
```

本队实现：`build/_e2e_matrix.py`（矩阵）、`build/_letterbox_check.py`（预处理/逆变换自检）、
`build/_fake_infer.py`（与板端 `ncnn_infer` 同解码/NMS 口径）。

### 2.3 letterbox 的逆变换

```python
scale = min(S / w, S / h)          # 等比缩放到 S×S，不拉伸
pad_x = (S - w * scale) / 2        # 居中补边（本队补 114 灰）
pad_y = (S - h * scale) / 2
# 网络坐标 → 原图坐标
x = (x_net - pad_x) / scale
y = (y_net - pad_y) / scale
```

### 2.4 读结果的顺序

1. 先核对「模型导出边长 == 评测边长」，不等就先修（见 §3 第一条）；
2. 再看同一模型内 letterbox 相对 squash 的变化（这是零成本项）；
3. 最后看跨边长的变化，并回答：涨分来自「尺度与训练一致」还是「参数更多」。

## 3. 失效条件（可观察现象）

| 条件 | 现象 | 处理 |
|---|---|---|
| 模型导出边长 ≠ 评测边长 | 召回**精确为 0.000**，两种预处理都 0；日志 `EXTRACT_FAIL` / `INPUT_FAIL` | 静态图把尺寸烧进 param，一个模型只能跑一个边长；重新导出并让文件名带尺寸 |
| 训练与评测的预处理不一致 | letterbox 的收益反转（甚至比 squash 差） | 预处理属于「模型的输入契约」，换预处理要重训或至少重评 |
| 评测集太小 / 真值框太少 | 两档差距在噪声内，无法归因 | 本队用 100 张 / 470 框；低于这个量级先把区间和样本量写清楚 |
| 只看训练框架 mAP | mAP 涨、部署召回不涨（解码/NMS/尺度不同） | 用部署代码 + 与板端同口径的替身，不要用训练脚本的验证集结果 |
| 未测板端耗时 | 召回涨了但帧率不可接受 | 换边长是**成本项**：先量 `INFER_MS`，再决定默认档 |
| 板端与 PC 的替身口径漂移 | PC 上对、板上不对 | 替身的解码/NMS/输入名必须与板端 C++ 逐项对齐（本队兼容 `in0/out0`） |

## 5. 已验证的效果

| 判据 | 结果 | 出处 |
|---|---|---|
| 部署同路径矩阵（470 框，micro） | 在板 320 squash **0.326** → letterbox **0.474**；微调 320/480/640 letterbox **0.549 / 0.689 / 0.668** | `build/_e2e_matrix.py`、`ai/sessions/029` |
| 板端复核 | 40 张图 / 191 个真值框：squash **0.476**、letterbox **0.623**；171 / 165 个框与主机逐框一致 | `ai/sessions/029` 轮次 3 |
| 板端耗时 | 单帧中位 1048 / 2566 / 5674 / 10470 ms（在板 320 / 微调 320 / 480 / 640） | `ai/sessions/029` 轮次 3 |
| 交叉验证 | 非零的 4 行与训练框架动态尺寸测量（0.396/0.544/0.597）吻合到 ±0.02 | `ai/sessions/029` |
| 预处理自检 | `LETTERBOX_CHECK OK` 9 项，含「squash 无补边」与「letterbox 上下各 70 行 114」互斥成立 | `build/_letterbox_check.py` |
| 尺寸契约 | 模型导出尺寸 ≠ 评测尺寸的 4 行全部为 0.000，其余 4 行非零 | `build/_e2e_matrix.py` |

> 判据是**能失败**的：尺寸不一致就会得到 0.000；补边行数或逆变换写错，自检直接 FAIL。
> **未验证**：`w05@480` 整段 250 帧的端到端耗时与稳定性（单帧 `INFER_MS` 已实测，D043 已定 480 为精度档、640 退役）。
